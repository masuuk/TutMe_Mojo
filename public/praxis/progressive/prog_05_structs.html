Structs, Traits & Fieldwise Init

Learn by doing. Start with a plain struct and progressively move toward traits, fieldwise initialization and generic functions over trait-constrained types.

How the Praxis Works

  5. If incorrect, try again — a hint unlocks after two misses, or reveal the solution.
Core concept: A struct's fields need explicit types. Mojo 1.x does not auto-generate a constructor — write def __init__(out self, …) or decorate the struct with @fieldwise_init. Traits like Stringable are conformed to by implementing their required methods.

1Level 1 — A Plain Struct

BeginnerFields

Challenge: What is printed?

struct Reading:
    var station: String
    var celsius: Float64

    def __init__(out self, station: String, celsius: Float64):
        self.station = station
        self.celsius = celsius

def main():
    var r = Reading("KIAMBU", 21.5)
    print(r.station, r.celsius)
No underscore means no magic here — the hand-written __init__ copies its arguments straight into the fields. What appears between the commas?
Solution 
KIAMBU 21.5

The hand-written __init__(out self, …) fills the two typed fields; printing shows both values.

2Level 2 — Mutating via mut self

Beginner+Methods

Challenge: What is printed?

struct Counter:
    var n: Int

    def __init__(out self):
        self.n = 0

    def bump(mut self):
        self.n += 1

def main():
    var c = Counter()
    c.bump()
    c.bump()
    c.bump()
    print(c.n)
Count how many times bump runs before the single print — each call adds one to the same self.n.
Solution 
3

Methods that change the struct take mut self — the same convention as mutating arguments. Three bumps leave n at 3.

3Level 3 — @fieldwise_init

IntermediateConstructors

Challenge: This struct has NO hand-written __init__. What is printed?

from std.collections import List

@fieldwise_init
struct Vec2:
    var x: Float64
    var y: Float64

def main():
    var v = Vec2(3.0, 4.0)
    print(v.x * v.x + v.y * v.y)
The @fieldwise_init decorator turns the field list into a positional constructor — (x, y) in order. Then just square and add.
Solution 
25.0

@fieldwise_init generates the constructor Vec2(x, y) from the field list. 3² + 4² = 25.

4Level 4 — Stringable

Intermediate+Traits

Challenge: What is printed?

struct Temp: Stringable:
    var c: Float64

    def __init__(out self, c: Float64):
        self.c = c

    def __str__(self) -> String:
        return String(self.c) + "C"

def main():
    var t = Temp(19.5)
    print(t)
Conforming to Stringable means print calls __str__. What does that method append to the number?
Solution 
19.5C

Conforming to Stringable means implementing __str__, so print(t) uses it directly.

5Level 5 — Generic over a Trait

AdvancedGenerics

Challenge: What is printed?

def larger[T: Comparable](a: T, b: T) -> T:
    if b > a:
        return b
    return a

def main():
    print(larger[Float64](2.5, 7.5))
    print(larger[Int](9, 4))
The same generic body runs twice with different type arguments — each call returns the larger of its two values. List both outputs.
Solution 
7.5
9

The [T: Comparable] constraint lets one function serve many types — the compiler specializes it per type argument.

6Level 6 — Expert Challenge

AdvancedCode Reasoning Modification

Challenge: The construction below fails to compile — BBox declares only fields. Add one line to fix it, keeping the positional construction.

struct BBox:
    var min_x: Float64
    var min_y: Float64
    var max_x: Float64
    var max_y: Float64

def main():
    var b = BBox(0.0, 0.0, 1.0, 1.0)
    print(b.max_x - b.min_x)
A struct with only fields needs help to build itself. Which decorator generates a positional constructor from exactly the field list?
Solution 
Possible solution

@fieldwise_init
struct BBox:
    var min_x: Float64
    ...

Mojo 1.x generates no implicit field initializer. @fieldwise_init above struct BBox creates the four-argument constructor, and the program prints 1.0.
