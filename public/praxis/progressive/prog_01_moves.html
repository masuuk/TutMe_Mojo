Ownership: Read, Mutate, Move

Learn by doing. Start with a simple read and progressively move toward mut mutation, var consumption, and move tracing.

Level 1 of 6
0 attempts

How the Praxis Works

  1. Read the code.
  2. Predict what happens.
  3. Submit your answer.
  4. If correct, move to the next level.
  5. If incorrect, try again — a hint unlocks after two misses, or reveal the solution.
Core concept: Arguments are immutable read-only references by default. mut lets a function mutate the caller's value; var takes ownership — pair it with ^ at the call site to transfer (move) a value out of its variable.

1Level 1 — A Read-Only Reference

BeginnerOutput Prediction

Challenge: What is printed?

def double(x: Int) -> Int:
    return x * 2

def main():
    print(double(21))
Nothing here mutates x — trace the arithmetic and it's a one-line answer.
Solution 
42

x is an immutable reference (the default): the function reads it but cannot change the caller's value. 21 × 2 = 42.

2Level 2 — Shadowing Meets Read-Only

Beginner+Scope

Challenge: What is printed?

def double(x: Int) -> Int:
    return x * 2

def main():
    var n = 5
    if n == 5:
        var n = 6
        print(double(n))
Which n is closest to the print call — the outer one or the one declared inside the if?
Solution 
12

The inner var n = 6 shadows the outer n inside the if block, so double(6) = 12 is printed.

3Level 3 — mut Mutation

Intermediatemut

Challenge: What is printed?

def bump(mut n: Int):
    n = n + 1

def main():
    var n = 10
    bump(n)
    print(n)
mut means the function sees the caller's real variable, not a copy. What does that do to n after the call?
Solution 
11

mut gives the function a mutable reference to the caller's variable, so the change to n is visible after the call. Note the caller writes bump(n) — no keyword repeated at the call site.

4Level 4 — Read-Only Can't Mutate

Intermediate+Conventions

Challenge: This version does NOT compile. Which line is wrong, and what keyword fixes it? (answer like: line a, mut)

def set_to_99(x: Int):
    x = 99          # line A

def main():
    var m = 1
    set_to_99(m)    # line B
    print(m)
One line tries to write to a parameter that was never given permission to be written to. Which convention grants that permission?
Solution

Line A is the culprit — declare x as mut:

def set_to_99(mut x: Int):
    x = 99

The default convention is a read-only reference, so x = 99 fails to compile. Changing the signature to def set_to_99(mut x: Int) fixes it, and main then prints 99.

5Level 5 — Move with ^

AdvancedOwnership Trace

Challenge: Predict the three lines printed.

def consume(var s: String):
    print("got:", s)

def main():
    var s = String("hello")
    print(len(s))
    consume(s^)
    print("done")
Three separate print calls run in order — list what each one outputs, one per line.
Solution 
5
got: hello
done

s^ transfers ownership into consume — no copy is made. The string's length is 5, then it is consumed, and done prints. After the move, s must not be used again.

6Level 6 — Expert Challenge

AdvancedCode Reasoning Modification

Challenge: The program below fails to compile. Rewrite it so it prints 10 then done using a mut function, and explain which argument convention each call uses.

def report(x: Int):
    x = x * 10
    print(x)

def main():
    var n = 1
    report(n)
    print("done")
The fix is a one-word change to the parameter's convention — which convention allows a parameter to be reassigned and have the caller see it?
Solution 
# Possible solution

def report(mut x: Int):
    x = x * 10
    print(x)

def main():
    var n = 1
    report(n)
    print("done")

Only mut permits the assignment inside report. The default convention is read-only, and var would require n^ at the call site and would move the value away. Reason about which convention each call needs — not just about matching the output.
