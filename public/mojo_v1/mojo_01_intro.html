Chapter 1

Introduction & Getting Started

What Mojo is, why it exists, how to install it, and how to write, run, and compile your first program.

1. What is Mojo?

Mojo is a programming language developed by Modular that combines the ergonomics of Python's syntax with the performance of systems languages like C++ and Rust. Version 1.0 marks the language's first stable release.

Mojo programs look familiar to any Python programmer — indentation-based blocks, def functions, readable control flow — but under the hood, Mojo is a very different machine:

  • Compiled, not interpreted. Mojo compiles ahead of time to native machine code. There is no interpreter adding overhead to every operation, which gives you fast and predictable performance.
  • Statically typed. Types are first-class. The compiler uses them to generate fast, specialized machine code instead of treating them as optional hints.
  • Ownership-based memory management. The compiler tracks which variables and fields control each value's lifetime, so memory is managed automatically — without a garbage collector or reference counting.
  • Value semantics by default. Assigning or passing a value typically creates an independent copy, keeping data flow clear and enabling safe parallelism.
  • Systems-level escape hatch. When you need low-level control — such as interfacing with C libraries — you can manage memory explicitly with pointers.
💡 Key Insight:

Mojo looks like Python but its execution model is closer to Rust, Swift, or C++. It brings together Python's readability with a performance model inspired by systems languages — "the usability of Python, the speed of C."

2. Why Mojo Exists

Python dominates AI and scientific computing, but its interpreter makes it too slow for performance-critical work. The traditional answer is the two-language problem: prototype in Python, then rewrite the hot paths in C++, CUDA, or Rust — maintaining two codebases, two toolchains, and a brittle bridge between them.

Mojo attacks this problem directly:

  • One language, all levels. Expressive high-level application code and low-level kernel code live side by side in the same file, same module, same type system.
  • Performance without ceremony. Fixed-width numeric types, SIMD vectors, compile-time parameterization, and explicit mutability give the compiler room to generate optimal code.
  • Safe parallelism. Because values are independent copies by default and the compiler enforces exclusivity for mutable access, data races are much harder to create accidentally.
  • Interop with both worlds. Mojo can call Python libraries and C libraries natively, so existing ecosystems remain usable (covered in Chapters 11).
🚀 Pro Tip:

If you already know Python, you have a head start: most syntax maps almost one-to-one. The new mental models you need are static types, value semantics, and ownership — exactly what this book teaches step by step.

3. Installing Mojo

You can install Mojo using any Python or Conda package manager, but Modular recommends either uv or pixi. Both approaches below install the stable build.

⚠️ System Requirements:

Mojo runs on Mac, Linux, and Windows via WSL. Make sure your platform is supported before installing.

# Install uv if you don't have it
curl -LsSf https://astral.sh/uv/install.sh | sh

# Option A: install into your environment
uv pip install mojo

# Option B: create a dedicated project
uv init temperature-analyzer
cd temperature-analyzer
uv add mojo
# Install pixi if you don't have it
curl -fsSL https://pixi.sh/install.sh | sh

# Create a project and install Mojo
pixi init temperature-analyzer \
    -c https://conda.modular.com/max/ \
    -c conda-forge
cd temperature-analyzer
pixi add mojo
pixi shell
💡 Notes:

The pixi flow activates a project shell with pixi shell; inside it, the mojo toolchain is on your PATH. With uv, the mojo command becomes available in the activated environment where you installed it.

4. Hello, Mojo!

Create a file called hello.mojo and add:

def main():
    print("Hello, Mojo!")

Run it from your terminal:

mojo hello.mojo
# Hello, Mojo!

If you see Hello, Mojo!, your setup works. Two things worth noticing already:

  • All Mojo executables use main() as their entry point.
  • Functions are declared with def — the same keyword Python uses.

A taste of real code

This small program previews several core features at once: typed collections, loops, function calls, and template strings:

def calculate_average(temps: List[Float64]) -> Float64:
    # The 0.0 floating-point literal defaults to Float64
    var total = 0.0
    for temp in temps:
        total += temp
    return total / Float64(len(temps))

def main():
    # [Float64] tells Mojo the `List` type at compile time
    var temps: List[Float64] = [20.5, 22.3, 19.8, 25.1]

    print("Recorded", len(temps), "temperatures")
    for index in range(len(temps)):  # The range is [0, len(temps))
        print(t" Day {index + 1}: {temps[index]}°C")

    var avg = calculate_average(temps)
    print(t"Average: {avg}°C")
💡 Key Insight:

The t"..." prefix creates a template string: braces {} interpolate expressions directly into the output. This is useful because it avoids memory allocations for intermediate values. You'll meet template strings properly in Chapter 3.

⚠️ Watch Out:

The range uses zero-based indexing, so day numbers are offset by 1 in the loop above — a detail carried straight from the official quickstart.

5. Running vs Compiling

There are two basic ways to execute Mojo code:

  • mojo hello.mojo — compiles and runs immediately, great for development.
  • mojo build hello.mojo — produces a standalone native executable you can ship and run without the toolchain present.
# Compile a standalone binary
mojo build hello.mojo

# Run the compiled program directly
./hello

Because the result is native machine code, the compiled program starts instantly and runs with no interpreter overhead. Later you'll also meet mojo build --emit shared-lib, which packages Mojo code as a dynamic library for Python or C to call (Chapter 11), plus flags for tuning compilation targets (Chapter 12).

🚀 Pro Tip:

Use mojo file.mojo while iterating — it feels like running a script. Switch to mojo build when you're ready to distribute or benchmark a real binary.

6. Mojo 1.x at a Glance

Five facts about Mojo 1.x syntax that will keep you oriented throughout this book:

Concept Mojo 1.x Syntax Notes
Functions def main(): def is the way.
Variables var x = 5 Variables are mutable by default. There is no let.
Compile-time values comptime N = 10 The comptime keyword marks values computed at compile time.
String formatting t"Hi {name}" Template strings interpolate expressions with no extra allocations.
Parameters vs arguments def f[count: Int](x: Int) Square brackets = compile-time parameters; parentheses = runtime arguments.
⚠️ Watch Out:

When a constructor takes ownership of self, it receives it as out self — so it reads def __init__(out self), not inout self. This book teaches the current language exclusively.
