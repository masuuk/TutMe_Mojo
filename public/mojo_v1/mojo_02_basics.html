Chapter 2

Language Basics

Variables and declarations, block scoping and shadowing, copying versus moving values, reference bindings, and compile-time constants.

1. Declaring Variables

A variable is a name that holds a value or object. All variables in Mojo are mutable by default — their value can change. To define a constant that can't change at runtime, use the comptime keyword (Section 5).

def main():
    var greeting: String = "Hello World"

A var declaration does three things:

  • Declares a logical storage location, tied to a particular type.
  • Binds the name to that storage location.
  • Initializes the storage with a newly created value. The new value is owned by the variable — no other variable can own it unless you transfer ownership (Section 3).

Inference, annotation, and deferred initialization

You can give a variable a value, a type annotation, or both. The more you annotate, the more explicit your code:

var a = 5              # Mojo infers that a is type Int
var b: Float64 = 3.14   # Explicit declaration of Float64 type
var c: String           # Name created but uninitialized (assigned later)

Types are permanent

A variable's type never changes. Its storage is strongly typed upon creation and can only hold values of that type:

var count = 8     # count is type Int
count = "Nine?"   # Error: can't implicitly convert 'StringLiteral' to 'Int'
🐍 In Python:

Names are untyped and the objects they point at carry the types, so count = 8 followed by count = "Nine?" is perfectly fine — the same name simply refers to something else. Mojo binds the type to the name, which is what turns a type error into a compile error instead of a surprise three lines later.

⚠️ Watch Out:

Immutability comes from never reassigning a name, or from comptime constants and immutable function arguments.

2. Scopes & Shadowing

Variables in Mojo use lexical scoping: a variable's definition is determined by where it appears in the source code, not when it executes at runtime. Variables have block-level scope:

  • Nested code can read and modify variables defined in an outer scope.
  • An outer scope can't read variables defined in an inner scope.
def lexical_scopes():
    var num = 1
    var dig = 1
    if num == 1:
        print("num:", num)   # Reads the outer-scope "num"
        var num = 2          # Creates a NEW inner-scope "num"
        print("num:", num)   # Reads the inner-scope "num"
        dig = 2              # Updates the outer-scope "dig"
    print("num:", num)       # Reads the outer-scope "num"
    print("dig:", dig)       # Reads the outer-scope "dig"

def main():
    lexical_scopes()

Output:

num: 1
num: 2
num: 1
dig: 2
💡 Key Insight:

The var statement inside the if creates a new variable with the same name as the outer one. This is called variable shadowing: the inner variable hides the outer one until the block ends. The inner num's lifetime ends exactly where the if block ends, because that's the scope in which it was defined.

3. Copying & Moving Values

An assignment of a newly created value establishes ownership:

var owning_variable = "Owned value"

An assignment of an existing variable's value either copies or transfers ownership:

var source = String("Hello")
var copied = source   # A copy — both names stay valid
var moved = source^   # A transfer — source is now uninitialized!
🐍 In Python:

Assignment copies a reference, never the value: copied = source and moved = source both leave you pointing at one and the same str object, and source stays valid throughout. There is no way to express "give this away and destroy my handle" in the language, so a large intermediate value silently stays alive.

The transfer sigil (^) moves the value to the new variable and leaves source uninitialized — you can't use it again until you assign it a new value. A transfer may move the value to a different memory location, so it requires the type to be Movable.

Implicitly copyable vs explicitly copyable

Simple value types like Int, Float64, and Bool conform to ImplicitlyCopyable, so plain assignment copies them automatically:

var one_value = 15
var another_value = one_value   # implicit copy — fine

Larger types like List are Copyable but not implicitly, because copying could be expensive. Assigning one without a transfer is an error:

var first: List[Int] = [1, 2, 3]
var second = first
# Error: 'List[Int]' is not implicitly copyable because
# it doesn't conform to 'ImplicitlyCopyable'

You have two clean options — copy explicitly, or move:

var first: List[Int] = [1, 2, 3]

var second = first.copy()   # Independent copy; `first` unchanged
second.append(4)             # [1, 2, 3, 4] — only in `second`
print(first)                 # [1, 2, 3]

var third = first^           # Transfer ownership; `first` unusable now
💡 Key Insight:

This is where Mojo most differs from Python. In Python, assignment binds a second name to the same object. In Mojo, assignment gives you an independent owned value — an automatic copy for trivial types, an error for expensive ones unless you say .copy() or ^. Data flow stays explicit, and safe parallelism falls out naturally. Full details in Chapter 7.

4. Reference Bindings

Sometimes you want Python-like aliasing instead of copies. When you retrieve a value from a collection, the collection returns a reference, not a copy — but assigning that reference to a var creates a copy (if the value is implicitly copyable):

var items: List[Int] = [99, 77, 33, 12]
var item = items[1]   # item is a COPY of items[1]

item += 1             # increments the copy
print(items[1])        # prints 77 — list untouched

To name a reference instead, use the ref keyword to create a reference binding:

var items: List[Int] = [99, 77, 33, 12]

ref item_ref = items[1]   # item_ref IS items[1] — no copy
item_ref += 1              # increments items[1]
print(items[1])            # prints 78

# ref item_ref = items[2]  # Error: invalid redefinition of item_ref
  • All reads and writes through item_ref go to the item it references — items[1].
  • Reference bindings cannot be reassigned; the binding is fixed at creation.
🚀 Pro Tip:

Mentally file these three tools together — var x = y (own a copy), var x = y^ (take over ownership), ref x = y (alias without owning). Choosing among them deliberately is the core skill of idiomatic Mojo. We build the full model in Chapter 7.

5. Compile-Time Constants

Since all variables are mutable by default, Mojo needs another way to express a value that can't change at runtime. That's the comptime keyword:

comptime MAX_RETRIES = 3
comptime GREETING = "Hello"

def main():
    print(t"{GREETING}, world! Retries: {MAX_RETRIES}")

A comptime value is computed once, at compile time, and cannot be reassigned. Beyond simple constants, comptime unlocks far more powerful metaprogramming — compile-time functions, loops, and reflection — covered thoroughly in Chapter 8.

💡 Key Insight:

Think of var as "runtime storage" and comptime as "compile-time knowledge." The compiler can fold comptime values directly into generated machine code — zero runtime cost.

6. Putting It Together

A small program exercising everything from this chapter:

comptime LIMIT = 5

def main():
    var scores: List[Float64] = [91.5, 84.0, 77.25, 98.5]

    # Reference binding: mutate the top score in place
    ref best = scores[3]
    best += 0.5

    # Copy: work on an independent snapshot
    var snapshot = scores.copy()
    snapshot[0] = 0.0

    # Shadowing inside the loop body block
    for i in range(len(scores)):
        var position = i + 1
        print(t"{position}: {scores[i]}")
        if position == LIMIT:
            print("Limit reached")

    print(t"original top score: {scores[3]}, snapshot first: {snapshot[0]}")
⚠️ Watch Out:

The snapshot edit (snapshot[0] = 0.0) does not affect scores — they're independent lists after .copy(). But the reference binding edit (best += 0.5) does change scores[3], because best aliases that slot.

📋 Summary:

You now know how Mojo stores, scopes, copies, moves, and aliases values — plus how to pin constants at compile time. Next we survey the type system itself: numbers, strings, SIMD vectors, tuples, and collections.
