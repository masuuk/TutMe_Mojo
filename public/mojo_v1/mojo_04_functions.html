Chapter 4

⚙️ Functions

Declarations, compile-time parameters vs runtime arguments, argument conventions and kinds, overloading, return values, and error propagation.

1. Anatomy of a Function

Mojo uses the def keyword to define functions. Functions declared inside a struct are called "methods," but they have all the same qualities as functions described here.

def function_name[
    parameters...          # compile-time values, in square brackets
](
    arguments...           # run-time values, in parentheses
) -> return_value_type:
    function_body
  • Parameters: optional compile-time values used for metaprogramming.
  • Arguments: optional run-time values passed into the function.
  • Return value: optional.
  • Body: required — but can be just pass.
def do_nothing():
    pass

Parameters vs arguments — a crucial distinction

In most languages "parameter" and "argument" are interchangeable. In Mojo they're different things:

  • An argument is a runtime value: add(a: Int, b: Int).
  • A parameter is a compile-time variable that becomes a runtime constant: repeat[count: Int](msg: String). The compiler generates a specialized version of the function for each unique parameter value used.
🚀 Pro Tip:

Mnemonic: square brackets = static (compile time); parentheses = passed at runtime. You'll use this constantly in Chapter 8.

2. Signature Rules

  • You must declare the type of every parameter and argument.
  • If a function doesn't return a value, omit the return type or declare None:
# These two definitions are equivalent
def greet(name: String):
    print("Hello,", name)

def greet(name: String) -> None:
    print("Hello,", name)
  • If the function returns a value, declare it with -> type — or provide a named result using the out convention (Section 6).
# These two definitions are equivalent
def incr(a: Int) -> Int:
    return a + 1

def incr(a: Int, out b: Int):
    b = a + 1

3. Arguments: Kinds & Conventions

Mutability convention

Function arguments are immutable by default — even though variables are mutable by default. This gives the compiler more room to optimize, and makes mutability visible in the signature:

def foo(value: Int):
    value += 1   # Error: expression must be mutable

def foo_mut(mut value: Int):
    value += 1   # Works — declared mutable with `mut`

The full set of argument conventions — out, var, mut, imm, and ref[origin] — is covered alongside ownership in Chapter 7.

Optional arguments & keywords

Arguments with defaults are optional and must come after required ones. Calls accept positional, keyword, or mixed forms:

def my_pow(base: Int, exp: Int = 2) -> Int:
    return base ** exp

var x = my_pow(3)              # Uses default exp=2 → 9
var y = my_pow(exp=3, base=2)  # Keywords, any order → 8
💡 Key Insight:

You can't give a default value to an argument declared with the mut convention — a mutable output slot doesn't make sense to "default."

Positional-only and keyword-only

Like Python, Mojo supports / and * separators in argument lists:

# Everything before / is positional-only
def minimum(a: Int, b: Int, /) -> Int:
    return a if a < b else b
# min(1, 2) OK — min(a=1, b=2) NOT OK

# Everything after * is keyword-only
def kw_only(a1: Int, a2: Int, *, double: Bool) -> Int:
    var product = a1 * a2
    return product * 2 if double else product

Positional-only suits names that carry no meaning for callers (and frees you to rename later). Arguments appear in a fixed order in any signature:

  1. Required positional arguments
  2. Optional positional arguments
  3. Variadic arguments (*args)
  4. Required keyword-only arguments
  5. Optional keyword-only arguments
  6. Variadic keyword arguments (**kwargs)

4. Variadic Arguments

Homogeneous variadics

*name: Type accepts any number of same-typed positional arguments, exposed as an iterable (and indexable) list:

def sum_all(*values: Int) -> Int:
    var total: Int = 0
    for value in values:
        total = total + value
    return total

print(sum_all(1, 2, 3))   # 6

# Mutate variadic elements via ref bindings...
def make_worldly(mut *strs: String):
    for ref i in strs:
        i += " world"

# ...or by direct indexing
def make_worldly2(mut *strs: String):
    for i in range(len(strs)):
        strs[i] += " world"
6

Heterogeneous variadics

To accept mixed types, pair a variadic type parameter list with the variadic argument. Iteration must happen at compile time with comptime for:

def count_many_things[*ArgTypes: Intable](*args: *ArgTypes) -> Int:
    var total = 0
    comptime for i in range(args.__len__()):
        total += Int(args[i])
    return total

print(count_many_things(5, 11.7, 12))   # 28
28

Callers never pass the type list — Mojo builds ArgTypes from the actual call.

Variadic keyword arguments

def print_nicely(var **kwargs: Int):
    for item in kwargs.items():
        print(item.key, "=", item.value)

print_nicely(a=7, y=8)
a = 7
y = 8

Limits worth knowing: kwargs require the var convention, all must share one Copyable type, dictionary unpacking (f(**d)) isn't supported yet, and neither are variadic keyword parameters.

5. Overloaded Functions

Because every declaration specifies exact types, supporting multiple types means writing multiple versions — overloading:

def add(x: Int, y: Int) -> Int:
    return x + y

def add(x: String, y: String) -> String:
    return x + y

print(add(1, 2))            # 3
print(add("mo", "jo"))       # mojo

When resolving a call, the compiler considers argument count/position/keywords, argument and parameter types, argument conventions, instance-vs-static method, and whether constructors are @implicit. Candidates are filtered in this precedence order:

  1. Fewest implicit conversions required
  2. No variadic arguments preferred
  3. No variadic parameters preferred
  4. Shorter parameter signature preferred
  5. Non-@staticmethod preferred
⚠️ Watch Out:

The compiler does not look at return type or the raises effect when resolving overloads. Two functions differing only in those are duplicate definitions and get rejected. If a call is genuinely ambiguous, disambiguate by explicitly constructing the argument type you want.

🚀 Pro Tip:

Overload sets can't be extended by imports or aliases — so from package import foo as imported_foo won't collide with your local foo.

6. Return Values

Return types use ->, values leave with return, and returned values are owned by the caller by default. Literals implicitly convert to the declared return type:

def get_greeting() -> String:
    return "Hello"   # StringLiteral implicitly converted to String

Named results (out)

Some values can't be moved or copied once constructed — returning them through a local variable would fail. The named result syntax fixes this: an out argument is an uninitialized slot the function fills in place. To the caller, it's completely transparent:

struct ImmovableObject:
    var name: String
    def __init__(out self, name: String):
        self.name = name^

# Build directly in the caller's storage — no move/copy needed
def create_immovable_object(name: String, out obj: ImmovableObject):
    obj = ImmovableObject(name^)
    obj.name += "!"
    # obj is implicitly returned if no return statement runs

def main():
    var my_obj = create_immovable_object("Blob")
    print(my_obj.name)   # Blob!

Rules: only one return value per function (either -> or one out); the out argument may sit anywhere in the list but convention goes last; if execution reaches the end without a return, the out value is what's returned.

💡 Key Insight:

This is exactly the mechanism behind struct constructors: def __init__(out self, ...) initializes self directly in the caller's storage. Same convention, same benefit.

7. Raising & Non-Raising Functions

Mojo functions are non-raising by default. A function that can propagate an error must say so with raises; a non-raising caller must handle errors from anything it calls:

def raises_error() raises:
    raise Error("There was an error.")

# Will not compile:
def unhandled_error():
    raises_error()   # Error: can't call raising function in a non-raising context

# Handle it explicitly:
def handle_error():
    try:
        raises_error()
    except e:
        print("Handled an error:", e)

# Or propagate it:
def propagate_error() raises:
    raises_error()

Mojo also supports typed errors, where you declare which custom error type a function raises: def validate(value: Int) raises ValidationError -> Int. The full error-handling model — typed errors, stack traces, context managers — is Chapter 10.

🚀 Pro Tip:

Treat raises as part of the contract, visible in every signature. Because it's checked at compile time, forgetting to handle an error path is a build failure — not a production surprise.
