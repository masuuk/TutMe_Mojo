🔒 Closures & Lambda Expressions

Nested functions with explicit capture lists, the four capture conventions, move-captures with ^, anonymous single-expression lambdas, and what it means for a lambda to be thin.

1. Closures: Nested Functions with Capture Lists

A closure is a nested function with a capture list that controls how it accesses values from its enclosing scope:

def main():
    var multiplier = 3
    def scale(x: Int) {imm multiplier} -> Int:
        return x * multiplier
    print(scale(5))   # 15
15

{imm multiplier} references multiplier from the enclosing scope as an immutable reference. Without the capture list, referencing any outer value is a compile error — Mojo never captures implicitly by accident.

A closure is created when its enclosing def runs and exists only for the lifetime of that enclosing scope. A closure is Copyable when every value it captures is Copyable.

Syntax

The capture list appears immediately before the return arrow; effects like raises go between the argument list and the capture list:

def name(argument-list) {capture-list} -> ReturnType:
    body

def name(argument-list) raises {capture-list} -> ReturnType:
    body

The capture list can be empty ({}) or omitted entirely — both forms prohibit references to outer values. {} is preferred when the absence of captures is intentional, because the explicit braces make the constraint visible.

Capture list grammar

A capture list is a brace-enclosed, comma-separated sequence of entries:

FormMeaning
<conv> nameCapture name with convention <conv>
<conv>Default convention for all free variables
nameCapture name with convention imm
<conv> name^Move-capture (only with var or no convention)

<conv> is one of imm, mut, var, ref. Position within the list isn't significant, and at most one entry can omit a name (the default-convention entry).

2. The Four Capture Conventions

imm — observe the current state

The closure observes the outer value's current state at each call:

def main():
    var limit = 10
    def check(x: Int) {imm limit} -> Bool:
        return x < limit
    print(check(5))    # True
    limit = 3
    print(check(5))    # False
True
False

mut — writes go back to the outer binding

def main():
    var total = 0
    def accumulate(x: Int) {mut total}:
        total += x
    accumulate(10)
    accumulate(20)
    print(total)   # 30
30

var — an owned copy, frozen at declaration

The copy constructor runs once, when the closure is declared. Later changes to the outer binding don't affect the closure's copy, and vice versa:

def main():
    var snapshot = 42
    def frozen() {var snapshot} -> Int:
        return snapshot
    snapshot = 999
    print(frozen())   # 42
42
⚠️ Watch Out:

Capturing a large List or String by var allocates at the closure declaration. Use imm or mut when an independent copy isn't needed.

Move capture: var name^

Transfers ownership of the name into the closure. The outer binding is consumed; using it after the closure declaration is a compile error:

def main():
    var data: List[Int] = [1, 2, 3]
    def take_data() {var data^}:
        print(data)
    take_data()      # [1, 2, 3]
    # print(data)    # error: 'data' is uninitialized after move

Move capture skips the copy that var name would perform, and it's the only way to capture a move-only type by value. The ^ marker is only legal on var entries or bare names: {imm name^}, {mut name^}, and {ref name^} are rejected.

Copyable closures: {var^}

A default move-capture makes the closure value itself Copyable when every captured type is:

def main():
    var label = "sensor-1"
    def tag() {var^} -> String:
        return label
    var clone = tag     # closure value copied
    print(tag())     # sensor-1
    print(clone())    # sensor-1
sensor-1
sensor-1

ref — forward the origin's mutability

ref is the only convention that forwards origin information unchanged: the closure doesn't pick imm or mut, it inherits whatever the outer binding's origin carries. It's intended for parameterized code that must operate across mutability contexts — in ordinary closures, imm and mut produce clearer signatures.

3. Mixing Conventions & Default Conventions

Each entry carries its own convention independently:

def main():
    var config = "prod"
    var count = 0
    var label = "run-1"
    def process() {imm config, mut count, var label}:
        count += 1
        print(config, count, label)
    process()     # prod 1 run-1
    label = "run-2"
    process()     # prod 2 run-1  (label copied at declaration)
prod 1 run-1
prod 2 run-1

A bare name in a mixed list uses imm — not the convention of its neighbors. A convention keyword without a name sets the default for every free variable not named explicitly:

def main():
    var a = 1
    var b = 2
    var z = "snapshot"
    def mixed() {mut, var z}:
        a += 10     # 'a' uses default: mut
        b += 20     # 'b' uses default: mut
        print(a, b, z)
    mixed()       # 11 22 snapshot
    z = "changed"
    mixed()       # 21 42 snapshot  ('z' was copied at declaration)

Rules: at most one default-convention entry per list; position isn't significant; the default doesn't apply to names covered by an explicit entry.

Parametric closures

A closure can declare its own compile-time parameter list — name[parameters](arguments) effects {captures} -> ReturnType:

def main():
    # The `Intable` trait supports `Int` conversion
    def double[T: Intable](x: T) {} -> Int:
        return Int(x) * 2
    print(double[Int](5))         # 10
    print(double[Float64](3.4))   # 6
10
6

Nesting

Closures can nest inside closures, each with its own capture list — and closures are values, so an inner closure can capture an outer one by name:

def main():
    def make_adder(n: Int):
        def add(x: Int) {var n} -> Int:
            return x + n
        def twice(x: Int) {var add} -> Int:
            return add(add(x))
        print(twice(5))   # add(add(5)) = add(8) = 11
    make_adder(3)
11

4. Restrictions

  • No escape. A closure can't outlive its enclosing scope. Returning a closure from its declaring function, or storing it past the enclosing scope's end, isn't supported. Mojo doesn't support escaping closures or async execution.
  • No heap-allocated closures. You could allocate heap memory and copy a closure into it manually, but Mojo doesn't provide a built-in mechanism for heap-allocated or existential closures.
  • No thin or abi("C") on declarations. These apply only to closure types used as function parameters; a declaration with captures can't be thin.
💡 Key Insight:

Because capture lists are explicit, every ownership question about a closure is answered in the declaration itself. The compiler's error table maps each mistake to its trigger: a ^ without var, a duplicate default convention, an unterminated capture list, or a reference to an outer name the capture list doesn't cover.

5. Lambda Expressions

A lambda is an anonymous, single-expression function. It has no name, its body is a single expression, and it doesn't use return:

def main():
    var inc = lambda (x: Int) -> Int: x + 1
    print(inc(4))   # 5
5

Lambdas complement def: use def for named, reusable functions and lambdas for short, inline behavior — higher-order programming, callbacks, event handlers.

Syntax

Most parts are optional; every lambda includes the lambda keyword, a body expression, and the : that introduces it:

lambda [[parameter-list]] [(argument-list)] [effects] [{capture-list}] [-> ResultType]: expression
def main():
    # Fully explicit. Empty "no-capture" capture list `{}`
    var a = lambda (x: Int) {} -> Int: x + 1
    # Parameterized
    var b = lambda [T: Intable](x: T) -> Int: Int(x) + 1
    var y = 1
    # Capture list omitted. `y` defaults to `imm`
    var c = lambda (x: Int) -> Int: x * 2 + y
    # Mutable capture, return type omitted (`None`)
    var list: List[Int] = [1]
    var d = lambda (x: Int) {mut list}: list.append(x)
    # Arguments and return type omitted. Mutable capture
    var e = lambda {mut list}: list.append(0)
    print(a(4), b(4))   # 5 8
5 8
⚠️ Active Development:

Return-type inference isn't implemented. If you omit the return type, the lambda returns None — even when its body produces a value: lambda (x: Int) {}: x + 1 fails with "can't convert Int to None". Always declare -> Int.

Arguments & capture rules

  • Each argument must appear in parentheses and have a type — there's no argument-type inference from the use site. Arguments use the same conventions as functions; the default is imm.
  • Variadic arguments work: *args and **kwargs (the latter packs into an OwnedKwargsDict, so declare it with var).
  • A lambda becomes a closure when its body references an enclosing value (defaulting to imm capture), uses an explicit capture convention, or declares its own parameter list. Capture conventions are the same as nested def closures.
  • An empty capture list {} means "capture nothing" — referencing an enclosing variable is then an error.
var list: List[Int] = [1, 2, 3]
var f = lambda (x: Int) {mut list}: list.append(x)
f(10)
print(list)   # [1, 2, 3, 10]
[1, 2, 3, 10]
🚀 Pro Tip:

{mut list} beats {mut}: naming captures limits them to list and turns accidental references into errors instead of silent captures.

Effects & nesting

Effects go after the argument list and before the capture list. A lambda body is a single expression, so it can't contain a raise statement — declaring raises lets a lambda propagate errors from what it calls, not raise them itself:

def apply_raising(f: def (x: Int) raises thin -> Int, arg: Int) raises -> Int:
    return f(arg)

def main() raises:
    print(apply_raising(lambda (x: Int) raises -> Int: x + 1, 2))   # 3
3

Lambdas nest: an inner lambda references the outer one's parameters directly and captures its arguments through its own capture list:

def main():
    var f = lambda (x: Int) {} -> Int:
        (lambda (y: Int) {imm x} -> Int: y + x)(3)
    print(f(6))   # 9
9

6. Thin Lambdas

A lambda that isn't a closure is thin: it captures nothing, uses no explicit capture conventions, and doesn't declare its own parameters. Thin lambdas can be:

  • Used as a thin function pointer, including abi("C") callbacks.
  • Passed as a thin function-type parameter.
  • Bound to a symbol with comptime.
  • Returned from a function, stored in a struct field, or used as a default argument value.

Thin matters when a lambda must outlive the scope that created it or is needed at compile time — capturing closures can't do either.

C ABI boundaries

Thin lambdas cross C ABI boundaries because they carry no runtime state. The abi("C") effect must appear on the lambda declaration — typing the variable isn't enough:

var fp = lambda (a: Int32, b: Int32) abi("C") -> Int32: a + b
print(fp(1, 2))   # 3
3

Compile-time execution

Mojo can execute thin lambdas at compile time and assign the result to a comptime name:

def main():
    comptime whole = (lambda (x: Int) {} -> Int: x * 2)(21)
    print(whole)   # 42
42

📋 Summary:

Closures make outer state explicit: every capture names its convention, and the compiler rejects anything the list doesn't cover. Lambdas give you inline, single-expression functions — thin when they capture nothing, closures when they carry state. With both, the function-declaration family from Chapter 4 is complete.
