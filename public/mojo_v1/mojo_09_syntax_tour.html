Chapter 9

🔀 Mojo vs Python: A Syntax Tour

Seven classic problems implemented in Mojo 1.x. Each one is a single program, with the Python habit it replaces called out in prose — the fastest way to internalize the syntax if you already write Python.

1. Quadratic Equation Solver

Given coefficients a, b, and c, solve ax² + bx + c = 0 using the quadratic formula. This example shows function signatures, conditionals, and error handling in a single screen.

Like Python, Mojo uses indentation — not curly braces — to delimit blocks. Where Python opens a block with a colon and indents, Mojo does exactly the same: there are no { } in sight.

def solve_quadratic(a: Float64, b: Float64, c: Float64) raises -> (Float64, Float64):
    var discriminant = b * b - 4.0 * a * c
    if discriminant < 0.0:
        raise "No real roots"
    var root1 = (-b + discriminant ** 0.5) / (2.0 * a)
    var root2 = (-b - discriminant ** 0.5) / (2.0 * a)
    return (root1, root2)

def main():
    var r1, r2 = solve_quadratic(1.0, -5.0, 6.0)
    print("x1 =", r1, "x2 =", r2)
💡 Key Insight:

Mojo raises errors like Python — even a bare string works as shorthand for raise Error("No real roots"). One difference: the function must declare it with the raises keyword in its signature, so callers know at a glance that the call can fail. The square root needs no import either: discriminant ** 0.5 is the Mojo spelling of Python's math.sqrt(discriminant), because ** is overloaded for Float64.

2. Compound Interest

Calculate accumulated value using A = P(1 + r/n)^(nt). This highlights how Mojo handles exponentiation, floating-point arithmetic, and formatted output.

def compound_interest(
    principal: Float64,
    rate: Float64,
    times_per_year: Int,
    years: Int
) -> Float64:
    var n = Float64(times_per_year)
    var t = Float64(years)
    var base = 1.0 + rate / n
    return principal * base ** (n * t)

def main():
    var amount = compound_interest(10000.0, 0.05, 12, 10)
    print("Accumulated:", amount)
🚀 Pro Tip:

Both languages use the ** operator for exponentiation, and Mojo's version accepts float exponents directly on Float64 values — no import needed. Note the explicit conversions: Mojo won't silently mix Int and Float64 arithmetic the way Python does. Formatted output splits the same way: Python's f"Accumulated: {amount:.2f}" becomes a t-string, t"Accumulated: {amount:.2f}".

3. Net Present Value (NPV)

Discount a series of future cash flows back to present value using NPV = Σ CF_t / (1 + r)^t. This showcases loops, accumulation, and the interplay between integers and floats.

def npv(rate: Float64, cash_flows: List[Float64]) -> Float64:
    var total: Float64 = 0.0
    for t in range(len(cash_flows)):
        total += cash_flows[t] / (1.0 + rate) ** Float64(t)
    return total

def main():
    var flows: List[Float64] = [-1000.0, 300.0, 420.0, 680.0]
    var result = npv(0.08, flows)
    print("NPV =", result)
⚠️ Watch Out:

Mojo's ** operator handles Float64 exponents directly. In production finance code, prefer an integer exponent when you can — it's faster and avoids floating-point drift in the discount factor. There is no enumerate either: the loop walks indices with range(len(cash_flows)) and indexes the list, which is why the exponent is cast with Float64(t) instead of being used bare.

4. Simultaneous Equations (Cramer's Rule)

Solve a 2×2 system using Cramer's rule. This example demonstrates structs — Mojo's struct, taking over the job Python's @dataclass does.

@fieldwise_init
struct System2x2:
    var a1: Float64
    var b1: Float64
    var c1: Float64
    var a2: Float64
    var b2: Float64
    var c2: Float64

    def solve(self) raises -> (Float64, Float64):
        var det = self.a1 * self.b2 - self.a2 * self.b1
        if det == 0.0:
            raise "No unique solution"
        var x = (self.c1 * self.b2 - self.c2 * self.b1) / det
        var y = (self.a1 * self.c2 - self.a2 * self.c1) / det
        return (x, y)

def main():
    # 2x + 3y = 8,  4x - y = 2
    var sys = System2x2(2.0, 3.0, 8.0, 4.0, -1.0, 2.0)
    var x, y = sys.solve()
    print("x =", x, "y =", y)
💡 Key Insight:

@fieldwise_init generates a field-by-field constructor — Mojo's answer to Python's @dataclass. When you need custom initialization logic instead, write an explicit def __init__(out self, ...): the out convention marks self as uninitialized on entry and fully initialized on return.

5. Factorial (Iterative & Recursive)

Implement factorial both iteratively and recursively. This highlights loops, recursion, type annotations, and how Mojo handles the base case.

def factorial_iter(n: Int) -> Int:
    var result: Int = 1
    for i in range(2, n + 1):
        result *= i
    return result

def factorial_rec(n: Int) -> Int:
    if n <= 1:
        return 1
    return n * factorial_rec(n - 1)

def main():
    for i in range(11):
        print(i, "! =", factorial_iter(i),
              "|", factorial_rec(i))
🚀 Pro Tip:

Mojo's Int is a fixed-size machine word, so add an explicit bounds check for negative inputs and watch for overflow on large factorials. Python's int has arbitrary precision, so overflow is never a concern.

6. Fibonacci Sequence

Generate the first N Fibonacci numbers. This example reveals how mutable state, list construction, and iteration patterns work in Mojo.

def fibonacci(n: Int) -> List[Int]:
    if n <= 0:
        return List[Int]()
    var seq = List[Int]()
    seq.append(0)
    if n > 1:
        seq.append(1)
    for i in range(2, n):
        var next_val = seq[i - 1] + seq[i - 2]
        seq.append(next_val)
    return seq

def main():
    var fib = fibonacci(15)
    for val in fib:
        print(val)
⚠️ Watch Out:

Mojo's List grows dynamically like Python's list. For performance-critical sequences, pre-allocate in Mojo with List[Int](capacity=n) to avoid repeated reallocations. Python's one-line " ".join(map(str, fib)) has no Mojo equivalent, so the driver loop just prints each value.

7. Syntax Cheat Sheet

A quick-reference table comparing core language features across Mojo 1.x and Python 3.12+.

Feature Mojo 1.x Python
Function definition def name(x: Int) -> Int: def name(x: int) -> int:
Mutable variable var x = 5 x = 5
Read-only binding ref r = value (no reassignment; no let) n/a — names always rebindable
Mutable parameter mut x: Int x: int (always pass-by-object)
Struct / class struct Foo: (+ traits) class Foo: / @dataclass
Constructor def __init__(out self): / @fieldwise_init def __init__(self):
Error handling raise + raises in signature / try/except raise / try/except
Print print("hi") print("hi")
String interpolation t"val = {x}" f"val = {x}"
For loop for i in range(n): for i in range(n):
Argument conventions Explicit: read-only (default), mut, owned, out None — implicit pass-by-object
Static typing Required on parameters; locals inferred Optional hints only
Compile-time metaprogramming Parameters [T], comptime, reflection Type hints / decorators only
Memory management Ownership + value semantics Garbage collector
Performance tier C / C++ level Interpreted
🚀 Pro Tip:

Bookmark this table. When migrating Python code to Mojo, focus on four transitions: (1) annotate parameter types — Mojo requires them, (2) replace classes with structs and declare trait conformance, (3) choose argument conventions deliberately instead of relying on Python's pass-by-object, and (4) use t"..." template strings instead of f-strings. The rest of the syntax maps almost 1-to-1.

📋 Summary:

Mojo borrows the best ideas from both worlds: Python's clean, readable syntax for everyday code, and compiled performance with explicit control over memory for high-performance systems. If you already know Python, you have a head start with Mojo.
