Chapter 3

Types & Values

The built-in numeric types and their SIMD foundation, strings and template strings, booleans, tuples, and the standard collection types.

1. A Nominal Type System

All values in Mojo have an associated data type. Most types are nominal ("named") — defined by a struct, with type equality determined by the type's name, not its structure. Two structs with identical fields are still different types.

A few things aren't structs:

  • Functions are typed based on their signatures.
  • NoneType is a type with one instance, None, used to signal "no value."
💡 Key Insight:

The standard library types aren't privileged — each one is defined just like a user-defined type, even basic ones like Int and String. When you define your own structs in Chapter 6, you're playing by exactly the same rules the language itself uses.

Built-in types (numerics, strings, booleans) are always available without imports. Everything else — collections, filesystem utilities, and so on — comes from the standard library.

2. Numeric Types

Mojo provides signed integers, unsigned integers, and floating-point values at multiple precisions.

Integers

The general-purpose integer type is the signed Int, which uses the system's native word size (typically 64 bits). For a specific bit width or unsigned arithmetic, use fixed-size types:

SignedUnsignedWidth
Int8UInt88-bit
Int16UInt1616-bit
Int32UInt3232-bit
Int64UInt6464-bit
Int128 / Int256UInt128 / UInt256128/256-bit
  • Ranges differ: Int8 holds −128…127; UInt8 holds 0…255 — same count of values, shifted range.
  • Overflow wraps: signed integers wrap into the negative range using two's complement (127 + 1 → −128 for Int8); unsigned integers wrap to the start of their range (255 + 1 → 0 for UInt8).
  • Default to Int unless you need a specific width — it keeps APIs consistent and predictable.

Floating point

Mojo follows IEEE 754-2008 for its main floating-point types:

TypeSignExponentMantissa
Float641 bit11 bits52 bits
Float321 bit8 bits23 bits
Float161 bit5 bits10 bits

There is no default floating-point type the way there's a default integer type — when starting out, stick to Float32 or Float64. For AI workloads Mojo also offers BFloat16 and the compact Float8_*/Float4_e2m1fn formats (GPU-oriented).

Special values like infinity and NaN are available as static constants on FloatLiteral:

from std.utils.numerics import isfinite, isinf, isnan

def main():
    var inf = FloatLiteral.infinity
    print(isinf(inf))       # True
    var nan = FloatLiteral.nan
    print(isnan(nan))       # True

Literals & materialization

Numeric literals support decimal, hex (0xaa), octal (0o77), binary (0b0111), and scientific notation (1.2e9; a float literal must include a decimal point). At compile time literals are treated as arbitrary-precision values; at runtime they materialize into finite-precision types — IntLiteral defaults to Int, FloatLiteral defaults to Float64:

var float1 = 3.3          # float1 is type Float64
var float2: Float32 = 7.5
var int1 = 5              # int1 is type Int
var int2: Int8 = 4

# Compile-time: exact, arbitrary precision
var arbitrary_precision = 3.0 * (4.0 / 3.0 - 1.0)

# Force runtime evaluation with a variable: rounding appears
var three = 3.0
var finite_precision = three * (4.0 / three - 1.0)
print(arbitrary_precision, finite_precision)
# 1.0 0.99999999999999978
⚠️ Watch Out:

Because floats are approximate, comparing them with == is rarely useful (1.0e16 == 1.0e16 + 1.0 prints True). Use </>=-style comparisons where possible, or compare within a tolerance using math.isclose().

3. SIMD: The Foundation of Numbers

Mojo implements its primitive numeric types as SIMD (single instruction, multiple data) vectors under the hood. A SIMD value is a fixed-size array of values that fits in a processor register, defined by two parameters: a DType value (the element data type) and the element count (a power of two):

# A vector of four Float32 values
var vec = SIMD[DType.float32, 4](3.0, 2.0, 2.0, 1.0)

# Math is applied elementwise
var vec1 = SIMD[DType.int8, 4](2, 3, 5, 7)
var vec2 = SIMD[DType.int8, 4](1, 2, 3, 4)
print(vec1 * vec2)   # [2, 6, 15, 28]

A scalar is just a one-element vector — Int, Int8, Float32, etc., are all type aliases for single-element SIMD values:

comptime Scalar = SIMD[length=1]
comptime Int = Scalar[DType.int]
comptime Int8 = Scalar[DType.int8]
comptime Float32 = Scalar[DType.float32]

This means whether you're working with a single Float32 or a wide vector of them, operations go through exactly the same code path — and the compiler can use one hardware instruction for many values.

Conversion

Numeric operators never automatically widen or narrow operands — convert explicitly with cast(), or by constructing the target type:

var simd1 = SIMD[DType.float32, 4](2.2, 3.3, 4.4, 5.5)
var simd2 = SIMD[DType.int16, 4](-1, 2, -3, 4)

# Convert with cast()
var simd3 = simd1 * simd2.cast[DType.float32]()
# Convert with the SIMD constructor
var simd4 = simd2 + SIMD[DType.int16, 4](simd1)

# Scalars: construct the target type
var my_int: Int16 = 12
var result = Float32(my_int) * 0.75   # 9.0
🚀 Pro Tip:

Note that DType.float64 is not a type — it's a value describing a data type. You can't declare a variable of type DType.float64; you declare SIMD[DType.float64, 1] — or just write Float64.

4. Strings

String is Mojo's primary text type: a mutable, UTF-8 encoded string with an ergonomic API:

var s: String = "Testing"
s += " Mojo strings"
print(s)   # Testing Mojo strings

# Explicit conversion with String(...)
var s1 = "Items in list: " + String(5)
# Variadic construction — no per-value String() needed
var s2 = String("Items in list: ", 5)

Emoji and grapheme clusters

Source files are UTF-8, so emoji work directly in literals (var wave = "👋"). The standard library counts characters three different ways, and they usually disagree:

  • byte_length() — number of UTF-8 bytes
  • count_codepoints() — Unicode code points
  • count_graphemes() — user-perceived characters (UAX #29)
def show(label: StaticString, s: StringSpan):
    print(label, "bytes=", s.byte_length(),
          "codepoints=", s.count_codepoints(),
          "graphemes=", s.count_graphemes())

def main():
    show("wave ", "👋🏽")
wave  bytes=8 codepoints=2 graphemes=1

A skin-tone wave emoji is one grapheme built from two code points. To avoid non-ASCII bytes in source, spell code points with hex escapes: "\U0001F44B" (8-digit form, up to U+10FFFF), "\u00A9" (4-digit, up to U+FFFF), or chr(0x1F44B).

Raw strings & literals

print(r"Hello\nWorld")     # Prints Hello\nWorld literally

# Adjacent literals concatenate across lines
comptime s = "A very long string which is "
             "broken into two literals for legibility."

# Triple quotes for multi-line text
comptime doc = """
Multi-line string literals let you
enter long blocks of text."""
💡 Key Insight:

A string literal has the compile-time type StringLiteral and materializes to a runtime String when needed: comptime param = "foo" stays a literal; var runtime_value = "bar" is a String.

5. Template Strings (TStrings)

Mojo also offers the classic "{0} {1}".format(a, b) style, but the modern tool is the template string — the t"..." prefix you've already seen:

var count = 3
var items = "apples"
var template = t"Give me {count} {items}."
print(template)            # Give me 3 apples.

var x = 41
print(t"The answer is {x + 1}")   # No allocation!

var list = [1, 2, 3]
print(t"{list[0] + list[1]}")      # 3 — arbitrary expressions OK

var name = "Nate"
var s = String(t"Hello, {name}!")  # Explicit allocation only here
  • TStrings insert the Writable representation of any expression between braces.
  • They're lazy: nothing allocates until you explicitly construct a String — printing writes pieces straight to output.
  • Raw template strings (rt"...") interpolate but don't expand escapes: rt"Hello,\t{name}." keeps the backslash-t.
⚠️ Watch Out:

Python's f-string syntax doesn't exist in Mojo — it's t"...", not f"...". If you catch yourself typing f", swap the prefix.

6. Booleans & Truthiness

Bool takes exactly two values, True and False, negated with not:

var conditionA = False
var conditionB: Bool
conditionB = not conditionA
print(conditionA, conditionB)   # False True

Many other types have a boolean representation through the Boolable trait. The general principles:

  • Collections evaluate as True if they contain any elements, False if empty.
  • Strings evaluate as True if they have non-zero length.

You'll see this used constantly with Optional below, and in if/while conditions in Chapter 5.

7. Tuples

A Tuple is a lightweight, fixed-size, heterogeneous collection with value semantics. Its size and element types are fixed, though individual elements can be mutated:

# Explicitly typed...
var example_tuple = Tuple[Int, String](1, "Example")

# ...or inferred from a literal
var pair = (1, "Example")

# Unpack into multiple variables
var x, y = pair
print(x, y)         # 1 Example

# Or index individual values
var s = pair[1]
print(s)            # Example
🚀 Pro Tip:

Tuples shine as lightweight return bundles — functions returning (Float64, Float64) pairs (like roots of an equation) combine perfectly with unpacking: var r1, r2 = solve_quadratic(...).

8. Collection Types

The standard library provides four core collection types, all parameterized on their element type(s) at compile time:

TypeDescriptionElement requirements
List[T]Dynamically-sized arrayCopyable
Dict[K, V]Associative array of key-value pairsK: KeyElement, V: Copyable
Set[T]Unordered unique items + set algebraKeyElement
Optional[T]A value that may or may not be presentCopyable

List

var l = List[String]()      # Empty, element type as parameter
var nums = [2, 3, 5]        # Literal infers List[Int]
var bytes: List[UInt8] = [2, 3, 5]   # Or pin the element type

nums.append(7)
nums.append(11)
print("Popping last item:", nums.pop())   # 11
for idx in range(len(nums)):
    print(nums[idx], end=", ")              # 2, 3, 5, 7,

# Comprehensions for compact conditional initialization
var squares = [i * i for i in range(5)]
Popping last item: 11
2, 3, 5, 7,
⚠️ Watch Out:

You can't print() a whole list or convert it directly to a string — print the individual elements instead (they just need to be Writable).

Iterating a List yields an immutable reference to each element. To mutate elements during iteration, capture each one with ref:

var list = [2, 3, 4]

for ref item in list:   # Capture a ref to the list element
    print(item, end=", ")
    item = 0            # Mutates the element inside the list

print("\nAfter loop:", list[0], list[1], list[2])
2, 3, 4,
After loop: 0 0 0

Dict

var empty_dict: Dict[String, Float64] = {}
var values: Dict[String, Float64] = {"pi": 3.14159, "e": 2.71828}
var d = Dict[String, Float64]()   # Constructor syntax works too

# Iterating items() yields references
var props: Dict[String, Float64] = {
    "plasticity": 3.1,
    "elasticity": 1.3,
}
for item in props.items():
    print(item.key, item.value)

Set

var i_like = {"sushi", "ice cream", "tacos", "pho"}
var you_like = {"burgers", "tacos", "salad", "ice cream"}

var we_like = i_like.intersection(you_like)
print("We both like:")
for item in we_like:
    print("-", item)
We both like:
- ice cream
- tacos

Optional

# With a value — two ways
var opt1 = Optional(5)
var opt2: Optional[Int] = 5

# Without a value — two ways
var opt3 = Optional[Int]()
var opt4: Optional[Int] = None

# Truthy when holding a value; guard before unwrapping
var opt: Optional[String] = "Testing"
if opt:
    var value_ref = opt.value()
    print(value_ref)

# Or supply a default
var greeting: Optional[String] = None
print(greeting.or_else("Hello"))   # Hello
greeting = "Hi"
print(greeting.or_else("Hello"))   # Hi
⚠️ Watch Out:

Calling value() on an empty Optional is undefined behavior. Always check truthiness first (as above) — that's what makes the pattern safe.

🚀 Pro Tip:

Where you need one variable that could hold, say, either an Int32 or a Float64, look at the Variant type — it holds exactly one of several listed types at a time.
