Chapter 6

Structs & Traits

Define your own types with fields and methods, then share behavior across types with traits — Mojo's compile-time polymorphism.

A struct is Mojo's primary way to define your own type: it bundles data (fields) together with the operations that act on that data (methods). Structs are defined at compile time — unlike dynamic Python classes, you cannot add or remove members while the program runs. That rigidity is the point: the compiler knows every field's exact location and type, so access is direct and fast.

Every standard-library type you've met so far — Int, String, List — is itself a struct. There is no special treatment for built-in types: your own structs have exactly the same powers.

A struct can define five kinds of members:

  • Fields — variables storing data
  • Methods — functions acting on field data
  • Static methods — functions provided by the type itself, no instance needed
  • Dunder methods — special double-underscore names like __init__() that hook into language behavior
  • comptime members — compile-time constants used for optimization

1. Defining a Struct

struct MyPair:
    var first: Int
    var second: Int

    def __init__(out self, first: Int, second: Int):
        self.first = first
        self.second = second

def main():
    var mine = MyPair(2, 4)
    print(mine.first)   # 2
2
  • All fields must be declared with var and a type annotation — no exceptions. This is what lets Mojo compute the struct's exact memory layout.
  • The constructor's first argument is out self: a mutable reference that starts uninitialized and must be fully initialized before the method returns. You never pass self yourself — Mojo supplies it.
  • You can't assign default values at the field declaration site; every field must be initialized inside the constructor.

@fieldwise_init

The most common constructor pattern — one argument per field — has a shortcut. The @fieldwise_init decorator generates it for you:

@fieldwise_init
struct MyPair:
    var first: Int
    var second: Int

# MyPair(2, 4) works exactly as before

If your type needs extra setup beyond field assignment, write __init__() by hand instead.

2. Constructing Instances

Beyond the ordinary call syntax MyPair(2, 4), Mojo supports initializer lists: if the target type is inferable from context, you can pass constructor arguments between braces:

var pair {2, 4}          # same as MyPair(2, 4)
# or with keywords:
# {first=2, second=4}
💡 Key Insight:

Person("Alice", 30) is syntactic sugar for calling the constructor directly: me = Person.__init__("Alice", 30). The compiler allocates stack space for the instance first, then __init__() fills it in.

3. Mutating Methods

By default, methods receive an immutable self and cannot modify fields. To mutate the instance, declare the receiver as mut self:

struct Counter:
    var value: Int

    def __init__(out self):
        self.value = 0

    def increment(mut self):
        self.value += 1   # OK with mut self

def main():
    var c = Counter()
    c.increment()
    c.increment()
    print(c.value)   # 2
2
⚠️ Watch Out:

With plain self, an assignment like self.value += 1 fails to compile: "expression must be mutable in assignment." The receiver convention is part of the method's signature — see Chapter 4's argument conventions.

4. Copying & Moving Structs

Mojo structs are neither copyable nor movable by default. Each of these fails for a bare struct:

var a = MyPair(1, 2)

var b = a      # ERROR: cannot be implicitly copied,
               # does not conform to 'ImplicitlyCopyable'

var c = a.copy()  # ERROR: same reason

var d = a^     # ERROR: cannot be copied or moved; consider
               # conforming to 'Copyable'

The fix is to opt in with traits:

TraitWhat you get
MovableMove-only: values can transfer ownership with ^. Mojo generates the move constructor.
CopyableCopies via .copy() and copy-initialization. Also adds movability — you never need both.
ImplicitlyCopyableCopies happen silently like Int. Use only when copying is cheap and side-effect free.
 
struct MyPair(Copyable):
    var first: Int
    var second: Int
    # Mojo synthesizes __init__(out self, *, copy: Self)

You'd write a custom copy constructor only when the default field-wise copy is wrong — for example, if the struct manages heap memory. Ownership mechanics are covered fully in Chapter 7.

5. Fields

Fields share the lifetime of their struct instance — created with it, destroyed with it. Rules and conventions:

  • var is mandatory on field declarations (unlike local variables).
  • Unique names: fields, methods, and comptime members share one namespace — no redeclaration.
  • Shadowing is fine: method arguments or locals may reuse a field's name; use self.field to reach the field.
  • No initializers at declaration: var foo: Int = 10 is an error; initialize in the constructor. (A comptime member can be initialized inline because it occupies no instance storage.)
struct MyStruct:
    var foo: Int

    def use_argument(self, foo: Int):   # argument shadows field
        print(foo)                     # prints argument value

    def use_local(self, value: Int):
        var foo = value                # local shadows field
        print(foo, self.foo)           # local first, then field

Naming conventions: lowercase snake_case (user_count); underscore prefix for internals (_private_field); boolean fields prefixed is_/has_; descriptive over type-based names.

6. Methods & Static Methods

Instance methods take the implicit self as their first argument — the only argument in a def whose type may be omitted, since Mojo already knows it. The name self is convention, not law.

@fieldwise_init
struct MyPair:
    var first: Int
    var second: Int

    def get_sum(self) -> Int:
        return self.first + self.second

var mine = MyPair(6, 8)
print(mine.get_sum())
14

@staticmethod

A static method belongs to the type, receives no self, and therefore can't touch fields. Call it on the type or on an instance — both work:

struct Logger:
    def __init__(out self):
        pass

    @staticmethod
    def log_info(message: String):
        print("Info:", message)

Logger.log_info("Called on type")
var l = Logger()
l.log_info("Called on instance")
Info: Called on type
Info: Called on instance
🚀 Pro Tip:

Static methods are also where "factory" helpers live — functions that construct specialized instances of the type, like Node.make_node() later in this chapter.

7. Lifecycle: Initialization & Destruction

Mojo tracks two distinct initialization states for every struct instance:

  • Fieldwise initialization — each field holds a valid value.
  • Logical initialization — the instance as a whole is valid, and its __init__() has run.

Populating fields by hand does not logically initialize the instance:

var me: Person
me.age = 25
me.height = 6

print(me)  # ERROR: used with all fields manually initialized
           # but without calling an '__init__' method

Inside __init__()

On entry, self is logically initialized but its fields are uninitialized — populating them is your job, all of them:

def __init__(out self, name: String, age: Int):
    self.name = name
    # ERROR if we stop here: field 'age' not initialized
    self.age = age

# Field sources can be anything: parameters, constants,
# or external values:
from std.math import pi
var default_angle = pi / 2.0
  • You can't call methods until every field is initialized — self.greet() before the last field assignment is an error.
  • Only __init__() methods may initialize individual fields of an uninitialized value; ordinary functions can't.

Moving out of a field deinitializes it

var me = Person("Connor", 25)
var name_owner = me.name^   # moves name out of me.name

print(me)          # ERROR: use of uninitialized value 'me'
me.name = "John"   # reinitialize the moved-from field...
print(me)          # ...and the instance is usable again

Destructors: __deinit__() and the deinit convention

The compiler destroys values at their last use (ASAP destruction). Customize that moment with __deinit__() — the 1.0 spelling, renamed from __del__() for parity with __init__() (the old name still compiles with a deprecation warning):

@fieldwise_init
struct Contact:
    var name: String
    var email: String

    def __deinit__(deinit self):
        # `self` still fully initialized here
        print("destroying contact")

Two special rules make destructors unique:

  • You may move fields out without reinitializing them (var name = self.name^) — the compiler knows this is the instance's final use. No other context allows this.
  • The deinit convention works on any method: a method whose receiver is deinit self is a destructor (useful for explicit-destruction designs). It also works on other arguments: def destroy_other(self, deinit other: Self).

8. Operator Overloading

Every operator maps to dunder methods. For a binary operator like + there are three forms:

  • Forward: a.__add__(b) — tried first.
  • Reverse: b.__radd__(a) — fallback for mixed types where the left operand doesn't know the right one (5 + a: Int knows nothing about your type).
  • In-place: a.__iadd__(b) — used by a += b; mutates instead of returning new.

Walkthrough: a Complex type

This condensed version of the official walkthrough demonstrates the main categories. Start with the base struct — traits supply equality, printing, and boolean conversion:

from std.math import sqrt

@fieldwise_init
struct Complex(Boolable, Equatable, Writable,
              TrivialRegisterPassable):
    var re: Float64
    var im: Float64

    # Convenience init: real part only
    def __init__(out self, re: Float64):
        self.re = re
        self.im = 0.0

def main():
    var c1 = Complex(-1.2, 6.5)
    var c2 = Complex(-1.2, 6.5)
    print(c1 == c2)          # True  (Equatable default)
True
💡 Key Insight:

Equatable supplies default __eq__/__ne__ via compile-time reflection over fields; Comparable derives <=, >, >= from just __lt__() and __eq__(). Types with no natural ordering (like complex numbers) should implement only Equatable.

Now add operators as methods:

    # Unary: +c and -c
    def __pos__(self) -> Self:
        return self

    def __neg__(self) -> Self:
        return Self(-self.re, -self.im)

    # Binary arithmetic (same-type shown; add Float64 overloads
    # plus __radd__/__rsub__/... to accept scalar on the left)
    def __add__(self, rhs: Self) -> Self:
        return Self(self.re + rhs.re, self.im + rhs.im)

    def __sub__(self, rhs: Self) -> Self:
        return Self(self.re - rhs.re, self.im - rhs.im)

    # In-place: modifies self, returns nothing
    def __iadd__(mut self, rhs: Self):
        self.re += rhs.re
        self.im += rhs.im

    # Boolean context: nonzero if either component nonzero
    def __bool__(self) -> Bool:
        return self.re != 0.0 or self.im != 0.0

    # Subscript: index 0 → real part, 1 → imaginary part
    def __getitem__(self, idx: Int) raises -> Float64:
        if idx == 0: return self.re
        if idx == 1: return self.im
        raise "index out of bounds"

    def __setitem__(mut self, idx: Int, value: Float64) raises:
        if idx == 0: self.re = value
        elif idx == 1: self.im = value
        else: raise "index out of bounds"

Slicing support

To support obj[1:5], accept a Slice parameter in __getitem__() and normalize it with indices(), which resolves omitted or negative bounds into concrete positions:

def __getitem__(self, span: Slice) -> Self:
    var start: Int
    var end: Int
    var step: Int
    start, end, step = span.indices(self.size)
    ...
🚀 Pro Tip:

Conform to Writable to make print() work: implement write_to(self, mut writer: Some[Writer]), and optionally write_repr_to() for the developer-facing repr() form — you can build it from a t-string: t"Complex(re={self.re}, im={self.im})".write_to(writer).

9. Traits: Contracts Between Types

A trait defines a contract — the methods, associated types, and compile-time values a type must provide. Traits are Mojo's pathway to polymorphism: write one function against the trait, and any conforming type can use it, verified entirely at compile time.

trait DeflectionSensing:
    def fetch_reading(self) -> Float64:
        ...   # ellipsis = required method

The full contract menu

MemberSyntaxMeaning
Required methoddef log(self, m: String): ...Every conforming type must implement it
Provided methoddef pause(self): passDefault implementation; types may override
Associated typeassociatedtype Element: MovableConforming types declare a subordinate type
Required comptime valuecomptime max_pause_seconds: Float64Each conforming type defines its own value
Shared constantcomptime tolerance: Float64 = 0.05One value shared by all conformers
Marker trait(no members)Marks a capability, requires nothing

A trait's default methods may call other required members of the same trait. Conformers inherit defaults and can override them, but there is no syntax to call the default from an override.

Conforming & refining

@fieldwise_init
struct CapacitiveSensor(Copyable, DeflectionSensing):
    def fetch_reading(self) -> Float64:
        return 21.5

# Refinement: inherits every requirement, adds new ones
trait CalibratableSensing(DeflectionSensing):
    def calibrate(mut self):
        ...
⚠️ Watch Out:
  • No duck typing: implementing the methods isn't enough — a struct conforms only if it declares the trait.
  • All or nothing: every requirement must be met (implemented or inherited). No partial conformance.
  • No retrofitting: you can't add traits to types you don't own; conformance is declared at definition.
  • Conflicting defaults: two traits providing the same default → compile error until your type implements it explicitly.
  • Structs have no inheritance and no static data members — traits are the substitute.

10. Generic Functions with Trait Bounds

Traits shine in parameterized functions. The compiler infers the type argument from the call site — no square brackets needed by callers:

def averaged_poll[
    SensorType: DeflectionSensing,
](sensor: SensorType, samples: Int) -> Float64:
    var total: Float64 = 0.0
    for _ in range(samples):
        total += sensor.fetch_reading()   # guaranteed to exist
    return total / Float64(samples)

var sensor = CapacitiveSensor()
print(averaged_poll(sensor, 10))   # SensorType inferred
21.5

Some[] shorthand vs named parameters

# Anonymous: don't need to name the type
def averaged_poll_2(sensor: Some[DeflectionSensing],
                   samples: Int) -> Float64: ...

# Named: needed when referring twice — e.g. two args of the same type
def compare_readings[SensorType: DeflectionSensing](
    a: SensorType, b: SensorType,
) -> Float64:
    return a.fetch_reading() - b.fetch_reading()

Combining traits

def poll_and_log[T: DeflectionSensing & Loggable](sensor: T):
    print(sensor.fetch_reading())
    sensor.log("Polling sensor")

# Reuse a combination via an alias:
comptime SensorLike = DeflectionSensing & Loggable

Refinement (trait B(A)) models "B is always an A." Composition (A & B) bundles independent capabilities for one function. Full treatment of compile-time parameters continues in Chapter 8.

11. Self-Referential Structs (Advanced)

Linked lists and trees need nodes that point at their own type — but a direct field is a compile error, because the layout would recurse forever:

struct Node:
    var value: String
    var next: Optional[Node]   # ERROR: Recursive reference

The solution: heap allocation + pointers. A pointer has fixed size regardless of what it points to. The canonical pattern from the docs:

struct Node[ElementType: ImplicitlyCopyable & Writable & Deinitable](
    Movable
):
    comptime NodePointer = Pointer[Self, MutUntrackedOrigin]
    var value: Optional[Self.ElementType]
    var next: Optional[Self.NodePointer]   # Optional = nullable

    @staticmethod
    def make_node(value: Self.ElementType) -> Self.NodePointer:
        var node_ptr = alloc[Self](1)        # 1. allocate space
        node_ptr.unsafe_write(Self(value))  # 2-3. init & move in
        return node_ptr                     # 4. return pointer

    def free_chain(self):
        var current = self.next
        while current:
            var cur_ptr = current.value()
            var next_node = cur_ptr[].next
            cur_ptr.unsafe_deinit_pointee()   # destroy value
            cur_ptr.unsafe_free()             # release memory
            current = next_node
  • MutUntrackedOrigin marks memory the lifetime checker doesn't track — allocation and deallocation are entirely your responsibility.
  • Pointer (unified with UnsafePointer in 1.0 — unsafety now lives on the individual unsafe_ operations) is non-nullable; wrapping it in Optional provides the null state with zero memory overhead.
  • The repeating pattern for reference structures: allocate → construct → move into place → return the pointer, and free each link explicitly when done.

📋 Chapter Summary:
  • Structs are static and layout-fixed — that's where the speed comes from.
  • All stdlib types are structs; your types have identical powers via dunders.
  • Initialization is two-phase: fieldwise vs logical — both required before use.
  • Traits replace inheritance: explicit conformance, compile-time verification.
  • Pointer-based patterns unlock graphs and linked structures safely.
